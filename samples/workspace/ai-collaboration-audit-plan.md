Reference review: 2026-09-24. **Every row remains pending implementation verification and live account comparison.** This is a reference-backed audit plan, not a claim that the twins implement these capabilities. The generated source inventory and a keyword scan are discovery aids; API route declarations or decorative presence indicators do not establish functional UI coverage.

Feature availability varies by account, plan, language, admin policy and product surface. Record those conditions with each reference observation. Use disposable fixtures and keep the real-account outbound and protected-data restrictions in the workspace instructions.

## Evidence required per state

For each discovered route/control, record its provider reference, account conditions, twin revision, principal/role, fixture, action and expected native outcome. Exercise success, error, cancellation, reload and post-reload native readback. Record the protected-state comparison and Twin Run teardown. Include desktop/narrow visual inspection and actual touch behavior; a width override is not touch-device coverage.

AI checks must validate supported effects and context boundaries, not a hard-coded congratulatory response. If a proposal can mutate state, the preview, commit and cancellation must be distinguishable in native readback. An unresolved or unavailable reference state stays pending. Never close a provider gate from this plan, an API route list, a source keyword match or a selected feature smoke test.
